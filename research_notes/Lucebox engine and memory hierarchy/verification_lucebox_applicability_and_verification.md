## Gaps closed

1. **The Lucebox engine's only iGPU-only recipe for this machine class.** The notes said only that a `ds4-strix` profile exists for V4, not V4.1, and gave no figures. RECOMMENDED_SETUPS.md now gives them. `--profile ds4-strix` sets `--max-ctx 131072 --chunk 8192 --ds4-fused-decode --ds4-fused-verify-f16-kv --ds4-expert-top-k 6 --ds4-prefill sparse`. It runs on one 128 GB Strix Halo (Radeon 8060S, ROCm 7.2.4) with the DSpark drafter and the ROCMFPX-MIX-STRIX artifact, all six routed experts. Measured: **42 tok/s decode and 320 tok/s prefill at 8K, 36 tok/s at 123K, 39 tok/s on code and math, 25 on prose** (PR #729).
   - The artifact is DeepSeek-V4-Flash-0731-ROCMFPX-MIX-STRIX.gguf: 98,294,917,184 B = 91.54 GiB, 2.766 bits per weight, 82/92 on Geometric's evaluation.
   - The drafter is 10,648,656,160 B.
   - Its own card (modified 2026-09-22) shows older numbers without the drafter: 18.1 tok/s "Quality" and 22.3 tok/s at top-4.
   - This is ROCm/HIP only and lossy. The node can instead run 0731 losslessly in its own llama.cpp (gap 5).
   - Sources: https://github.com/Luce-Org/lucebox/blob/main/server/docs/RECOMMENDED_SETUPS.md ; DS4.md lines 156–164 and 986–994 ; https://huggingface.co/Lucebox/DeepSeek-V4-Flash-0731-ROCmFP3
2. **What antirez Q2 is made of.** The notes listed this as open. The full role breakdown is in row 18. That breakdown resets the calibration factor from 73% to 65%.
3. **Whether PR #28696 brings backend kernels.** The notes listed this as open. It brings none: the diff touches no `ggml/` file. V4.1 therefore runs on whatever backend already runs V4's DSV4 ops, plus six generic ops. Whether that works on Vulkan is still untested (open gap below).
4. **Which V4.1 files fit fully resident.** Besides antirez Q2 (151.76 GiB main), Lucebox's `ds41-lucebox-final` (152.15 GiB) and `-minus10gib` (142.13 GiB) fit, and they score higher on Lucebox's bench (row 20). ROCMFP2S (167.58 GiB main) does not fit without spill.
5. **The real alternative to a 2-bit V4.1: lossless 0731.** Unsloth's UD-Q8_K_XL is 150.75 GiB and bit-exact with the official weights. It runs on the pinned v0.4.1 (deepseek4 arch present).
   - **Cross-file observation (not in the checked file):** `docs/ATLAS_FRAMEWORK_REVIEW.md` line 317 says Q8 "would leave about 2 GiB for the KV cache where Q4 leaves about 9". That subtracts 162 **GB** and 155 **GB** from 164 **GiB**. In GiB the headroom is about 13.2 GiB for Q8 and 19.6 GiB for Q4.
   - Compute buffers and the drafter (DSpark Q8_0 is 10.90 GB) still have to fit in that headroom, so whether Q8 is practical needs a measured load on the node. The unit mix-up is real.
   - Sources: https://huggingface.co/api/models/unsloth/DeepSeek-V4-Flash-0731-GGUF/tree/main?recursive=true ; https://unsloth.ai/docs/models/deepseek-v4
6. **A V4.1 engine the notes missed.** ik_llama.cpp has had `deepseek41` since 2026-09-21 (row 16). It is a CPU path the node could run without ROCm, but no CPU-only measurement on Zen 5 / Strix Halo exists.
7. **The replay setting of the no-dGPU baseline.** Framework's published run used decoder SWA bounded replay (row 5). Lucebox's 3× prefill claim is like-for-like on that setting.
