## Gaps closed

1. **When the 192 GB result was published.** The notes inferred that posts are revised after publication. This is now confirmed with dates. The V4.1 post's JSON-LD gives `datePublished` 2026-09-29 and `dateModified` 2026-10-06, and the post cites "Framework's … post of September 30, 2026". The engine repository added the 192 GB setup to DS41.md in commit #814 on 2026-10-06. The Wayback availability API lists a snapshot of the post at 2026-10-06 20:46 UTC. The 192 GB claims (49 tok/s, 3x, "nothing comes from the SSD") therefore date from about 6 October 2026, not 29 September.
2. **Wayback Machine.** The notes say it was unreachable. That is only partly true. `http://archive.org/wayback/available` works and lists snapshots: home 2026-06-11, /engine 2026-09-25, /hardware 2026-10-02, the V4.1 post 2026-10-06. The snapshot content itself still cannot be fetched: http returns 403 from the proxy, https gets a connection reset, and the CDX API resets. Earlier site versions therefore remain unread (see the open gaps).
3. **The iGPU name.** The notes listed this as unresolved. AMD's PRO 495 page names it "Radeon 8065S Graphics", 40 cores, codename "Gorgon Halo". The engine's `ds41-gorgon` profile describes the chip as "a 192 GB Gorgon Halo (gfx1151)", which is the same GPU ISA as Strix Halo. The System page's "Radeon 8060S" belongs to the 395 predecessor build.
4. **Engram I/O.** This was undocumented; mechanism and size are now known, though speed is still unmeasured. Engram tables cover layers 1 and 14 only. Each token reads 24 rows per layer, 264 B per row (256 FP8 values plus 8 scales), through buffered `pread` calls with WILLNEED hints, multi-threaded for 256 rows or more. That is 12.7 KB of payload per token, or at most 192 KiB of page reads when nothing is cached. On NVMe this is negligible at decode speed. During prefill at about 1,000 tok/s it is at most about 190 MB/s of random 4 KiB reads. These figures are computed from the source and config; the time each step spends on them is still unmeasured.
5. **How Lucebox runs each model it offers.** The notes covered only V4.1 in depth. The engine has exactly five launch profiles (launch_profiles.h at HEAD):
   - `ds4-strix`: DeepSeek V4 Flash on one Strix Halo (gfx1151), top-6, 131K context, sparse prefill.
   - `ds4-r9700-strix`: V4 Flash with dense work and hot experts on the R9700 and the remaining experts on Strix Halo, 18,432 context.
   - `ds41-lucebox`: V4.1 Flash on 128 GB with three tiers.
   - `ds41-gorgon`: V4.1 Flash on 192 GB with two tiers.
   - `qwen-next-r9700-strix`: Qwen3.8-Flash-Next with dense work, KV cache and the MTP drafter on the R9700 and the routed experts on Strix Halo.

   No profile runs V4.1 on an iGPU alone. `validate_model_features()` does not refuse a single-device V4.1 run, but no such run is measured anywhere. This matters for A.T.L.A.S., which has no R9700. `ds4-strix` (V4 Flash on one gfx1151 iGPU, all six experts) is the only Lucebox recipe written for that machine class.
6. **Qwen3.8-Flash-Next, a model on the Principal's list.** The notes did not include its measured speeds. Lucebox's card, using the Lucebox engine, UD-Q4_K_XL (103.69 GiB plus a 2.60 GiB MTP drafter), greedy decoding and a 131K context, reports:
   - Strix Halo iGPU **alone**: 40 tok/s decoding a short reply, 24–28 tok/s after a 16K prompt, 1,300 tok/s prefill at 16K.
   - With the R9700: 75 tok/s, 44–45 tok/s and 1,820 tok/s for the same three measures.

   The card does not say which Strix Halo (395 or PRO 495) was used. Source: https://huggingface.co/Lucebox/Qwen3.8-Flash-Next-GGUF/raw/main/README.md (repo created 2026-10-08).
7. **Upstream llama.cpp status for V4.1.** On 2026-10-15, llama.cpp master's `src/llama-arch.cpp` and `gguf-py/gguf/constants.py` contain `deepseek4` but no `deepseek41` architecture, so V4.1 is not merged upstream. Lucebox's loader accepts "the `deepseek41` keys (llama.cpp PR #28696 and DwarfStar dialects)" (DS41.md). `git ls-remote` shows `refs/pull/28696/head` 2076412 and `refs/pull/28696/merge` e11a1b7 still present, which is consistent with an open PR. The PR's state could not be read because the GitHub API is not enabled for that repository in this session. This agrees with the prior finding that V4.1 is unavailable on the v0.4.1 pin.
8. **R9700 interface and FLOPS.** AMD lists the R9700 as PCIe 5.0 x16, so the Lucebox x4 riser is a deliberate trade-off, which the engine works around by keeping state on the card. The "191 TFLOPS" figure is FP16 matrix (dense), not vector (47.8) and not sparse (383). See rows 11 and 16.

## Gaps still open

- **No Lucebox measurement on the Principal's exact configuration.** Nothing covers a 192 GB PRO 495 without the R9700, and no figure for a 128 GB Zero 495 (PRO 495) exists. The only "chip alone" V4.1 numbers are Framework's DwarfStar run (14.0 tok/s, or 16.3–16.5 with DSpark), which uses a different engine and quantization.
- **Engram time share.** How much of each step on 192 GB waits on Engram reads, and how much of the table stays in the page cache, is not measured. Only the per-token byte count was derived (gap closed 4).
- **Quality of the 192 GB recipe.** The router bias and decoder SWA bounded replay are not compared with an unbiased reference run. Only the KL table (for the files, not for the biased routing) and the 177-question bench exist. The bench is reported by Geometric, and its "with DSpark" column ran with the Lucebox profile.
- **The 368.4 GB card.** Whether it deliberately counts both drafters, or whether the GiB reading is what Lucebox intends, is not stated by Lucebox.
- **Earlier site versions.** Snapshot content is blocked (http 403, https reset). The price history therefore still rests on dated press articles. Notebookcheck (2026-09-22: $5,999 Developer, $7,999 Business, "Batch 4 … November 2026", "86 tokens per second") was re-read and confirmed. Runtimewire and the HN price comment were not re-checked in this pass.
- **Unchanged from the notes:** the "optional cloud fallback" is undefined; the Zero 495's firmware and OS versions, SSD model and compute-board maker are not published; funding amounts are unknown; Reddit, X and YouTube sources are unread; GitHub stars and contributors come only from Lucebox's own `/api/github-stars` (2,921) and the YC page, not from GitHub (API blocked).
- **Which Strix Halo produced the Qwen3.8-Flash-Next figures,** and whether `ds4-strix` (V4 Flash) has been run on a 192 GB PRO 495. Neither is stated anywhere.
