# A.T.L.A.S. outbound allowlist (Section 12.5, CONVENTIONS.md §7.1). One squid dstdomain per line.
# A leading dot matches the domain and every subdomain (".hf.co" = cdn-lfs.hf.co, xet.hf.co ...). Wildcards are
# used only where a vendor spreads one service over unpredictable subdomains; otherwise hosts are named one by one.
# Lines starting with # and blank lines are stripped by phase1/04-system.sh before the file reaches squid.
# Everything not listed here is denied by squid (TCP_DENIED/403 in /var/log/squid/access.log) and by ufw
# (only the squid user may open outbound 80/443). To find a missing host after a failure:
#   grep TCP_DENIED /var/log/squid/access.log | awk '{print $7}' | sort | uniq -c | sort -rn | head
# then add it here (in the repository copy) and reload the proxy WITHOUT re-running step 4:
#   sudo /opt/atlas/day1/phase1-platform.sh --reload-allowlist /path/to/repo/scripts/day1/config/allowlist.txt
# (copies the file over /opt/atlas/day1/config/allowlist.txt, re-renders, `systemctl reload squid`; no ufw reset,
# no dist-upgrade, no reboot). `--force 04` is NOT the way: it resets ufw, repeats the update and ends in a reboot.
#
# NOT outbound (never listed): ntfy at http://127.0.0.1:8090 and http://<LAN_IP>:8090 is loopback/LAN; every
# llama-server, Redis, ChromaDB, Kokoro, Whisper, Open WebUI and orchestrator port is loopback/LAN; WireGuard is
# UDP 51820 and bypasses the proxy by protocol (ufw allows it explicitly).
# NEVER listed, by rule §7.1 "nothing cloud": api.openai.com, api.anthropic.com, generativelanguage.googleapis.com
# (Gemini). Because Gemini lives under googleapis.com, the Google group below names explicit hosts and never the
# ".googleapis.com" wildcard. api.openwebui.com (Open WebUI update and community checks, R8) also stays out.
