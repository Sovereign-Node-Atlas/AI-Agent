# A leading dot matches the domain and every subdomain (".hf.co" = cdn-lfs.hf.co, xet.hf.co ...). Wildcards are
# used only where a vendor spreads one service over unpredictable subdomains; otherwise hosts are named one by one.
# Lines starting with # and blank lines are stripped by phase1/04-system.sh before the file reaches squid.
# Everything not listed here is denied by squid (TCP_DENIED/403 in /var/log/squid/access.log) and by ufw
# (only the squid user may open outbound 80/443). To find a missing host after a failure:
#   grep TCP_DENIED /var/log/squid/access.log | awk '{print $7}' | sort | uniq -c | sort -rn | head
# then add it here (in the repository copy) and reload the proxy WITHOUT re-running step 4:
#   sudo /opt/atlas/day1/phase1-platform.sh --reload-allowlist /path/to/repo/scripts/day1/config/allowlist.txt
# (copies the file over /opt/atlas/day1/config/allowlist.txt, re-renders squid AND the host DNS forwarder (dnsmasq),
# reloads both; no ufw reset, no dist-upgrade, no reboot). `--force 04` is NOT the way: it resets ufw, repeats the
# update and ends in a reboot.
# HOST DNS (Section 12.5): dnsmasq forwards to the LAN resolvers exactly the names listed here plus two names derived
# from /etc/atlas/atlas.env settings, $DOMAIN (so V5 can resolve $VPN_HOST) and the host part of $WINDOWS_SHARE when
# it is a name; everything else is NXDOMAIN. Nothing else is added by any script (rule §7.1: this file and nothing else).
# A host listed only for DNS/UDP (not HTTP) says so in its comment; squid would admit it on 80/443 too, which is why
# only Canonical's NTP hosts are in that position.
